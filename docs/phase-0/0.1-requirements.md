# 0.1 — Requirements Specification

Status: **Defaults adopted for v1 (24 Sep 2026)**. Items marked ❓ are covered by the decisions in §5. Three items (Q1, Q11, Q13) are still open.

## 1. Scope

**In scope:** outbound calls to admitted applicants to confirm whether they will take admission. Outcome capture, retries, result datasets, recordings/transcripts, and an admin dashboard.

**Out of scope (v1):** inbound calls, fee collection, document verification, any calls not about admission confirmation, SMS/WhatsApp (proposed for v2).

## 2. Functional requirements

| ID | Requirement | Acceptance criterion | Phase |
|---|---|---|---|
| **F-01** | Upload applicant dataset as CSV or Excel | A 10,000-row file uploads and validates in under 30 s. Rejected rows are reported with row number and reason | 3 |
| F-02 | Required fields: name, phone, gender, program. Optional: preferred language, applicant ID, any extra columns | Missing required columns block the upload with a clear message. Extra columns are passed through to result files | 3 |
| F-03 | Phones normalised to E.164. Pakistani local formats accepted. Duplicates detected | Audit tool results match manual checks on a sample | 0/3 |
| **F-10** | Bot calls every valid applicant in the campaign | 100% of callable applicants get ≥ 1 attempt unless the campaign is stopped | 3 |
| F-11 | Goal of each call: will the student take admission (yes / no / not sure) and, if no, the reason | ≥ 90% of connected calls end with a clear outcome (pilot metric) | 2 |
| F-12 | Female students → female voice "Sara". Male students → male voice "Ali". Unknown → configurable default ❓ | Persona matches gender in 100% of test calls | 2 |
| F-13 | The bot never claims to be human. If sincerely asked, it answers honestly and continues. Upfront disclosure where law requires it (EU/EEA) | 100% pass on "are you a bot?" scenarios | 2 |
| F-14 | Languages: Urdu, English, Punjabi, Sindhi, Arabic, Hindi at launch. Pashto in pilot. Saraiki/Balochi/Hindko go to a human | Language auto-detected and switched mid-call in scenario tests | 2 |
| F-15 | Recording notice at the start of every call | Present in 100% of recordings | 2 |
| **F-20** | Call target 1–2 min. Wrap-up at 90 s, hard stop at 120 s | 95th percentile of connected calls ≤ 120 s | 2 |
| F-21 | Strictly on topic. Redirect off-topic talk up to N times (default 2 ❓). Then end politely and mark as escalation | Scenario tests pass | 2 |
| F-22 | Answers on-topic questions (fee, deadline, orientation) only from configured campaign facts. Never invents | 0 invented facts in tests and pilot | 2 |
| F-23 | Honours "don't call me again" immediately: never retried, marked `opted_out` | Scenario tests pass | 2 |
| **F-30** | Output `confirmed.csv`, `declined.csv` (with reason), `no_answer.csv`, `escalation.csv`, `all_calls.csv` | Files downloadable any time during and after the campaign | 3 |
| F-31 | Every record: timestamp, call duration, language used, attempts, outcome, short summary | Columns present in every file | 3 |
| F-32 | Automatic retries for no answer / busy / failed / voicemail / dropped / callback requested. Configurable attempts (default 3) and gaps (default 3 h, then 24 h) ❓ | Retry timing verified in tests | 3 |
| F-33 | Calls only within calling windows in the recipient's local time (default 10:00–13:00 and 15:00–19:30, Mon–Sat ❓) | 0 calls outside windows in load test | 3 |
| F-34 | Recordings and transcripts stored for audit with a retention policy (90 days / 1 year ❓) | Lifecycle rule verified | 3 |
| **F-40** | Admin dashboard: upload, start/pause/resume, kill switch, live progress, downloads | Usable by admissions staff without training beyond a 1-page guide | 4 |
| F-41 | Escalation queue: staff resolve escalated calls with a final outcome | Resolved outcomes update the result files | 4 |
| F-42 | Roles: viewer / operator / admin. Downloads and recording playback are logged | Audit log entries present | 4 |

## 3. Non-functional requirements

| ID | Requirement | Target |
|---|---|---|
| N-01 | Capacity | 10,000 applicants per campaign, ≥ 10 concurrent calls. First pass completes in ≤ 3 working days |
| N-02 | Conversational latency | Median agent response ≤ 1.2 s after the student stops speaking |
| N-03 | Reliability | 0 lost call results (webhook idempotency). 0 duplicate dials of the same attempt |
| N-04 | Accuracy | ≥ 97% agreement with human review on confirmed/declined. Uncertain calls go to escalation, never mis-filed |
| N-05 | Cost | ≤ $0.30 per student (target ~$0.23, Option B) |
| N-06 | Security & privacy | See [05-data-privacy-security.md](../05-data-privacy-security.md). No real data in git. Encryption at rest |
| N-07 | Compliance | Legal checklist signed ([0.5-legal-signoff.md](0.5-legal-signoff.md)) |
| N-08 | Operability | Pause/resume without losing state. Kill switch stops dialling within 5 s |

## 4. Success metrics (pilot and campaign)

| Metric | Pilot gate | Campaign target |
|---|---|---|
| Connect rate (answered / attempted students) | ≥ 60% | ≥ 90% after retries |
| Clear outcome rate (of connected) | ≥ 90% | ≥ 92% |
| Complaint rate | < 2% | < 1% |
| Human-review agreement | ≥ 95% | ≥ 97% |
| Average connected call length | ≤ 100 s | ≤ 90 s |
| Staff hours for the whole campaign | — | ≤ 20% of the manual process |
