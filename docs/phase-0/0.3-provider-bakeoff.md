# 0.3 — Provider Bake-off (STT · TTS · LLM · Platform)

**Goal:** choose providers on measured quality **in our languages over phone-quality audio**, not on marketing claims. STT/TTS is only about $0.03 of the ~$0.10 per AI minute, so quality decides, not price.

## 1. Candidates

| Layer | Candidates | Config |
|---|---|---|
| Speech-to-text | ElevenLabs Scribe v2, Deepgram Nova-3 | [`bakeoff/candidates.json`](../../bakeoff/candidates.json) |
| Text-to-speech | ElevenLabs Flash v2.5, Azure Neural (Uzma/Asad for Urdu, plus Pashto/Arabic/Hindi voices), Uplift AI (Urdu/regional; manual samples until API access) | same |
| In-call LLM | Claude Haiku 4.5 (base estimate), Claude Sonnet 5. Others if the platform offers them | Tested inside the platform (§4) |
| Voice platform | Vapi (primary), Retell (fallback) | Trial accounts |

## 2. Test material

[`bakeoff/test-phrases.json`](../../bakeoff/test-phrases.json) has **11 phrases × 7 languages** (Urdu, English, Punjabi-Shahmukhi, Sindhi, Pashto, Arabic, Hindi):
- **S1–S8: what students say.** Used for STT. Covers confirm, decline with reason, undecided, parent answering, "are you a robot?", fee question, opt-out, and a name + program.
- **A2–A4: what the agent says.** Used for TTS. Covers the confirmation question, asking for a reason, and a date.

> ⚠️ Non-English lines are **drafts** and must be corrected by a native speaker before recording. Gendered verb forms are deliberate (S1 male, S2 female).

## 3. How to run

```bash
cp .env.example .env            # add ELEVENLABS_API_KEY, DEEPGRAM_API_KEY, AZURE_SPEECH_KEY/REGION
npm run bakeoff -- check        # phrase coverage, which keys are present, recordings found
npm run bakeoff -- roundtrip    # quick machine check: TTS the student lines → STT → CER
npm run bakeoff -- tts          # agent lines per provider/voice → bakeoff/out/tts/ + tts-scoring.csv
npm run bakeoff -- stt          # native-speaker recordings → stt-results.csv + stt-summary.md
```

### Recording native speakers (the STT test that matters)

1. Per language, at least **2 speakers (1 female, 1 male)**, ideally 3–4 with different accents. For example, for Urdu: Lahore, Karachi and Peshawar speakers.
2. Each speaker reads **S1–S8 naturally** (not slowly), and also improvises one sentence per intent in their own words.
3. **Record over a real phone call** to capture 8 kHz telephone audio (for example, call a staff line with recording on). Or record on a phone and downsample: `ffmpeg -i in.m4a -ar 8000 -ac 1 out.wav`
4. Save as `bakeoff/recordings/<lang>/<speaker>_<phraseId>.wav`, for example `bakeoff/recordings/ur/lahore-f1_S2.wav`. This folder is git-ignored because it contains staff voices.

### TTS listening test

Open `bakeoff/out/tts-scoring.csv`. Two native reviewers per language score each sample on:
- **Naturalness** (1–5)
- **Pronunciation** (1–5), especially the university name, program names and dates
- **Voice matches the persona gender** (Y/N)

## 4. In-call LLM + platform test

On a Vapi trial account, configure the Sara assistant with [`prompts/agent-system-prompt.md`](../../prompts/agent-system-prompt.md) and run **10 scripted calls per LLM**: confirm, decline, off-topic ×3, "are you a bot?", Urdu↔English switching, parent answers. Measure:
- **Response latency**: time from the student stopping to the agent starting to speak. Target a median ≤ 1.2 s.
- **Rule adherence**: no invented facts, honest disclosure, redirect limit, `record_outcome` called once.
- Repeat 3 of the calls on Retell for comparison.

## 5. Scoring & decision

| Criterion | Weight | Measure | Pass bar |
|---|---:|---|---|
| STT accuracy (Urdu) | 25% | Mean CER on phone audio | ≤ 10% |
| STT accuracy (other launch languages) | 15% | Mean CER | ≤ 20% (Pashto ≤ 30%) |
| TTS naturalness & pronunciation | 25% | Mean of reviewer scores | ≥ 4.0 Urdu, ≥ 3.5 others |
| End-to-end latency | 15% | Median response time | ≤ 1.2 s |
| LLM rule adherence | 10% | Scenario pass rate | 100% on safety/disclosure, ≥ 90% overall |
| Cost | 5% | From [01-cost-estimate.md](../01-cost-estimate.md) | Within budget |
| Vendor terms (DPA, retention, no training on our data) | 5% | Document review | Required |

A language whose best combination fails its pass bar launches as **Urdu fallback + human escalation** (see [03-conversation-design.md §5](../03-conversation-design.md)).
