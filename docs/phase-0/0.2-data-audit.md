# 0.2 — Data Audit

**Goal:** find out, before any call is placed, how many applicants can actually be called and what needs fixing at the source. Examples: bad numbers, missing gender, siblings sharing one phone.

## Tool

```bash
npm run audit -- path/to/export.xlsx --out data/audit-report.md
```

- Reads **CSV or Excel**. Column names are matched loosely ("Mobile No", "Student Name", "Programme"… all work).
- Produces a Markdown report: summary, column mapping, gender / language / country / mobile network / program breakdowns, row-level issues, and an estimated campaign cost for that file.
- Phone numbers in the report are **masked** (`+9230*****567`).
- Put real exports and reports in `data/`. That folder is git-ignored, so they never reach GitHub.

## Result on the synthetic sample

[`data-audit-sample-report.md`](data-audit-sample-report.md) was run on [`samples/applicants.sample.csv`](../../samples/applicants.sample.csv) (20 rows seeded with typical problems):

| Check | Result |
|---|---|
| Callable | 17 / 20 |
| Rejected | 2 (missing name, 5-digit phone) |
| Duplicates | 1 (same mobile as another applicant, typically siblings or a parent's phone) |
| Unknown gender | 2 (blank, "X") → default persona |
| Unrecognised language | 1 ("Klingon") → auto-detect |
| Landline | 1 (`042-…`, callable but more likely to be answered by someone other than the student) |
| International | 3 (UAE, KSA, UK) → international route + `upfront` disclosure for UK |

## Cleaning rules (applied automatically)

| # | Rule | Where |
|---|---|---|
| 1 | Header aliases, case- and punctuation-insensitive | `mapHeaders` |
| 2 | Phones: strip spaces/dashes, `00`→`+`, repair `92…` / `3xxxxxxxxx` / Excel `.0`, default country PK, E.164 | `normalizePhone` |
| 3 | No name, or no valid phone → **rejected** (listed by row) | `validateRows` |
| 4 | Repeated phone → first row kept, later rows listed as **duplicates** for manual review | `validateRows` |
| 5 | Gender: F/Female/M/Male + Urdu words. Anything else → `unknown` → default persona | `normalizeGender` |
| 6 | Language: English names, ISO codes, Urdu/native script. Unknown → auto-detect | `normalizeLanguage` |
| 7 | Extra columns (city, CNIC-free fields only) passed through to result files | `validateRows` |

## Recommendations for the admissions export

1. **Export gender for every applicant.** It decides Sara/Ali and the grammar the bot uses.
2. **Add a preferred-language column** to the application form if possible. It saves the first 10–20 seconds of every non-Urdu call.
3. **Collect the student's own mobile** separately from the parent's mobile. That removes most duplicates and "wrong person" callbacks.
4. **Don't include CNIC, marks, address or fee data** in the export sent to CallBot (data minimisation).
